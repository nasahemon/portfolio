Selected work

Real problems from production, what I did, and what changed.

Security · CI/CD

Removing stored cloud keys from CI

Revoking one key broke production builds for 14 services at once. Instead of a quick fix with a new service user, I moved all 19 repos to GitLab OIDC with least-privilege roles built from what the pipelines actually call. All 3 AWS accounts were fixed the same day.

Result: no stored AWS keys in CI; deploys restored across all environments.

Cost · Kubernetes

Cutting EKS cost by ~$8.7k/year

Pods reserved ~50× more CPU than they used, so clusters looked "full" and rolling deploys got stuck for hours. I right-sized requests (500m → 100m) and consolidated nodes with blue-green migrations.

Result: 18 → 11 nodes, ~56% less vCPU, zero downtime, production HA kept.

Security · Backend

Passwordless database access for 12 services

Spring's reactive database driver (R2DBC) has no IAM support, so I built a pattern that issues a fresh short-lived token for each connection. I shipped the infra changes first, switched off, then rolled out one service at a time.

Result: no DB passwords in config, 0 restarts during rollout, full TLS verification.

Platform · Upgrades

Production EKS 1.31 → 1.36

Five versions in a row, together with a blue-green move to Amazon Linux 2023 nodes, managed add-ons, and pinned versions to stop silent drift. Dev and staging went first.

Result: supported versions everywhere, and a ~$365/mo extended-support fee removed.

Infrastructure as Code

An isolated demo environment in one day

About 175 resources across 6 new Terraform modules. I checked capacity first (it wouldn't have fit), added a dedicated node group, and proved isolation from dev with negative tests.

Result: 22 of 22 services running on day one; dev untouched.

Secrets

Secrets out of git, into Vault

HashiCorp Vault with KMS auto-unseal, dynamic database credentials, and delivery through the Vault Secrets Operator. The 3-replica HA cluster was migrated to new nodes with no downtime.

Result: rotating DB credentials; plaintext secrets removed from the repo.

How this site ships

A small site, run like production. Every change goes through the same pipeline: checks on each pull request, a preview deployment, and a production release that is built once, smoke-tested, and only then promoted.

  1. Pull requestformat, HTML and link checks
  2. Previewbuilt once, deployed to a unique URL
  3. Merge to mainproduction build, not yet live
  4. Smoke testpages and security headers checked
  5. Promotethe tested build goes live; instant rollback
